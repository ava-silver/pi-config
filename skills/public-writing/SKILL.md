# Public writing

Make public-facing content clear on the first read without losing substance, nuance, or precision. Optimize for readers who may not know the subject or the organization.

Do not apply this skill to PR descriptions, code comments, or developer documentation unless the user asks for plain English or a broad audience. Use the `write` skill for ordinary technical prose.

## Structure

- Start with what the reader needs to know or do.
- Put the conclusion before detail and background.
- Keep one idea per sentence and one topic per paragraph.
- Use descriptive, sentence-case headings that help readers scan.
- Use numbered lists only for ordered steps.
- Give links descriptive text that makes sense out of context.

## Language

- Preserve important detail, but explain unfamiliar terms on first use.
- Prefer active voice, concrete nouns, and everyday words.
- Address the reader as "you" and the organization as "we" when appropriate.
- Use specific names, dates, and numbers instead of vague phrases.
- Remove repetition, throat-clearing, marketing language, clichés, and unnecessary jargon.
- Avoid Latin abbreviations. Write "for example" instead of "e.g." and "that is" instead of "i.e."

## Presentation

- Keep sentences and paragraphs short enough to scan, without enforcing a word quota.
- Use bold only for literal interface labels, such as **Save**, not for emphasis.
- Use sentence case for headings, titles, and table headers.
- Write dates as "June 4, 2026" and ranges with "to."
- Do not use all caps, exclamation marks, or FAQs as substitutes for clear structure.

Before finishing, check that a non-specialist can understand the main point and next action on the first read.
